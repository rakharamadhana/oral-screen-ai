# Swapping in a Retrained Model

How to put a newly trained model into this app. **The app only runs the model —
training happens in the separate project `../oral-disease-detector`.** This app
reads everything it needs (threshold, image size, normalization) from
`model_config.json` at runtime, so in the normal case you just replace 3 files.

---

## TL;DR

1. Retrain + export in `../oral-disease-detector` (produces 3 files).
2. Overwrite these 3 files in **`public/assets/models/`**:
   - `oral_referral_<architecture>_quant.onnx`
   - `model_config.json`
   - `fc_weights.json`
3. Bump `"version"` in `package.json` (it shows in the app footer).
4. Rebuild: `npm run build`, then `npx cap sync android` for the mobile app.

That's it — **no code changes** as long as the two rules below hold.

---

## The 3 files (in `public/assets/models/`)

| File | What it is |
|---|---|
| `oral_referral_<architecture>_quant.onnx` | The INT8-quantized model (~25 MB) |
| `model_config.json` | Threshold, image size, normalization, class names, architecture |
| `fc_weights.json` | Grad-CAM weights for the positive class (`{ "weights": [...] }`) |

Overwrite in place. You do **not** delete anything separately (unless the
architecture name changes — see Rule 1). Ignore the copies under `dist/` and
`android/app/src/main/assets/` — those are build output, regenerated by the
rebuild step. Never edit them by hand.

---

## Rule 1 — the `.onnx` filename must match the config

The app builds the model filename from the config, in
[`src/lib/inference.ts`](src/lib/inference.ts):

```ts
const modelUrl = `assets/models/oral_referral_${config.architecture}_quant.onnx`;
```

So the `.onnx` file must be named `oral_referral_<architecture>_quant.onnx`,
where `<architecture>` is the `"architecture"` value inside `model_config.json`.

- **Same backbone (`resnest50d`)** → filenames stay identical, just drag-and-drop
  replace. Nothing else to do.
- **Different backbone** (e.g. config says `"architecture": "efficientnet_b3"`)
  → name the file `oral_referral_efficientnet_b3_quant.onnx` to match, and
  **delete the old-named `.onnx`** so it doesn't ship as dead weight.

---

## Rule 2 — the model's input/output "contract"

For a no-code swap, the exported ONNX must keep these exact tensor names (the app
hardcodes them in [`src/lib/inference.ts`](src/lib/inference.ts) around lines
239–246):

| Tensor | Name | Shape |
|---|---|---|
| Input | `input_image` | `[1, 3, imgSize, imgSize]` |
| Output (score) | `logits` | `[1, 1]` |
| Output (for heatmap) | `features` | `[1, C, H, W]` |

- Probability = `sigmoid(logits[0])` = P(PERLU RUJUKAN).
- `fc_weights.json`'s `weights` array length **must equal `C`** (the feature
  channel count — currently 2048). `export_onnx.py` regenerates this to match.
- `H`/`W` (the CAM grid size) can change freely — the heatmap code reads the
  dimensions dynamically.

**If a tensor name differs** (e.g. the export names the score `output` instead of
`logits`), update those lines in `inference.ts`. **If the model has no
`features` output**, the heatmap simply won't render — the scan still works.

---

## `model_config.json` fields the app uses

```jsonc
{
  "classNames": ["TIDAK PERLU RUJUKAN", "PERLU RUJUKAN"],
  "positiveClass": "PERLU RUJUKAN",
  "decisionThreshold": 0.1281,   // sensitivity knob — read at runtime, never hardcoded
  "imgSize": 224,                // input resolution; preprocessing follows this
  "mean": [0.485, 0.456, 0.406], // normalization (must match training)
  "std":  [0.229, 0.224, 0.225],
  "architecture": "resnest50d",  // drives the .onnx filename (Rule 1)
  "testAuc": 0.908               // informational
}
```

Change the threshold, image size, or normalization here and the app adapts on
next load — no code edit needed.

## Where the new files come from (`../oral-disease-detector`)

| Step | Script |
|---|---|
| Prepare/split the dataset | `prepare_dataset.py` (data in `dataset_split/`) |
| Train + evaluate | `train_eval.py` |
| Export to ONNX | `export_onnx.py` (emits the `.onnx` + `fc_weights.json` + `model_config.json`) |
| INT8 quantize | `quantize_model.py` |

Copy the 3 outputs from there into this app's `public/assets/models/`.

---

## Before shipping a new model (medical safety)

This app is a **triage aid, not a diagnosis**. After retraining:

- **Re-tune the decision threshold** and write the chosen value into
  `model_config.json`. The current 0.1281 was tuned for high sensitivity.
- **Re-measure** sensitivity / specificity / AUC on a held-out test set (the
  training project has report generators, e.g. `Laporan_Performa_Model`).
- **Sanity-check parity**: score a few known images in the browser and confirm
  they match the Python pipeline within ~0.02 (canvas vs PIL resize differences).
- Make sure there is **consent / authorization** to use the images for training.

## Rebuild & verify

```bash
npm run build          # web build
npx cap sync android   # sync into the Android app
```

Then open the app, run a scan, and confirm:
- A known **PERLU RUJUKAN** image → high score, referral verdict, heatmap over
  the lesion.
- A **TIDAK PERLU RUJUKAN** image → low score, no-referral verdict.

If the model fails to load into WASM memory on Android, add
`android:largeHeap="true"` to `android/app/src/main/AndroidManifest.xml`.
Do **not** gzip the `.onnx` in any build step — it's already compressed.
